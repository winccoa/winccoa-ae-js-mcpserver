# WinCC OA MCP Server - Quick Start Guide

**Version 1.4.0** | AI Integration for Industrial Automation

This Model Context Protocol (MCP) server connects AI assistants to WinCC OA SCADA systems.

## Prerequisites

- WinCC OA 3.20 or higher (3.21 required for dashboard tools)
- WinCC OA JavaScript Manager for Node.js
- Node.js v20+

## Setup

### 1. Extract

Extract this archive into your WinCC OA project's `javascript/` directory:

```
<YourProject>\javascript\mcpWinCCOA\
```

### 2. Install Dependencies

Open a command prompt in the `mcpWinCCOA` directory:

```cmd
cd <YourProject>\javascript\mcpWinCCOA
npm install
npm install --save-peer file:"C:/Program Files/Siemens/WinCC_OA/3.21/javascript/winccoa-manager"
```

Adjust the WinCC OA installation path to match your system, then confirm it resolved:

```cmd
node -e "console.log(require.resolve('winccoa-manager'))"
```

> **`--save-peer` is required on npm 11 and later.** Without it, `npm install file:...` **silently does
> nothing** for this package: it prints `added 25 packages`, exits 0, installs only the manager's own
> dependencies, and never creates `node_modules\winccoa-manager`. The server then fails at startup with
> `ERR_MODULE_NOT_FOUND: Cannot find package 'winccoa-manager'`.
>
> `winccoa-manager` is declared an *optional* `peerDependency`, and npm 11 no longer materialises those
> from a `file:` spec (verified: npm 10.9.4 does, npm 11.6.0 does not). `--save-peer` works on both.
> Neither `--include=peer`, `--include=optional`, `--legacy-peer-deps`, `--install-links`, nor running
> as Administrator makes any difference, and it is unrelated to the space in "Program Files".
>
> Note a later plain `npm install` or `npm ci` removes it again - that is what "optional" means to npm -
> so re-run the command above afterwards.

### 3. Configure

The `.env` file must be placed in the `build\` directory (next to `index_http.js`) - the server
resolves it relative to the running script. The template stays at the root, because `build\` is
regenerated by a build and anything kept only there is lost.

```cmd
copy .env.example build\.env
notepad build\.env
```

Set at minimum:

```env
# REQUIRED: Set your authentication token
MCP_API_TOKEN=your-secure-token-here

# Choose which tools to load (default is read-only)
# See .env.example for full list of available tools
```

**Default configuration loads read-only tools only.** To enable write operations (create datapoints, configure connections, etc.), update the `TOOLS` line in your `.env`. See `.env.example` for all available tools and categories.

### 4. Add JavaScript Manager

In the WinCC OA Console, add a new manager:
- **Manager Type:** JavaScript Manager (node)
- **Options:** `mcpWinCCOA/build/index_http.js`
- **Start mode:** always

### 5. Connect Your AI Tool

#### Claude Desktop

Edit Claude Desktop config (File > Settings > Developer > Edit Config):

```json
{
  "mcpServers": {
    "winccoa": {
      "command": "npx",
      "args": ["mcp-remote", "http://localhost:3000/mcp", "--header", "Authorization: Bearer YOUR_TOKEN_HERE"]
    }
  }
}
```

**Windows path issue?** If you see `"C:\Program" is either misspelled`, use this instead:

```json
{
  "mcpServers": {
    "winccoa": {
      "command": "cmd",
      "args": ["/c", "npx", "mcp-remote", "http://localhost:3000/mcp", "--header", "Authorization: Bearer YOUR_TOKEN_HERE"]
    }
  }
}
```

**Remote host?** Add `"--allow-http"` to the args array.

#### Claude Code (CLI)

```cmd
claude mcp add --transport http winccoa http://localhost:3000/mcp --header "Authorization: Bearer YOUR_TOKEN_HERE"
```

Replace `YOUR_TOKEN_HERE` with the token from your `.env` file. Restart your AI tool after configuration.

## Available Tool Categories

| Category | Description | Module(s) |
|----------|-------------|-----------|
| Datapoints | Read, write, create datapoints and types | `datapoints/dp_basic`, `dp_create`, `dp_set`, `dp_types`, `dp_type_create` |
| OPC UA | Connect to OPC UA servers, browse address space | `opcua/opcua_connection`, `opcua_address` |
| MQTT | Connect to MQTT brokers, map topics | `mqtt/mqtt_connection` |
| Alarms | Configure alarm thresholds | `alarms/alarm_set`, `alarm_delete` |
| Archives | Query and configure historical data | `archive/archive_query`, `archive_set`, `archive_delete` |
| Common Config | Set descriptions, aliases, units | `common/common_query`, `common_set`, `common_delete` |
| PV Range | Define min/max value ranges | `pv_range/pv_range_query`, `pv_range_set`, `pv_range_delete` |
| Manager | Control WinCC OA processes (Pmon) | `manager/manager_list`, `manager_control`, `manager_add`, `manager_remove`, `manager_properties` |
| Dashboards | Create visualization dashboards (requires 3.21) | `dashboards/dashboard`, `dashboards/widget` |
| Icons | Create custom SVG icons, browse 1400+ built-in icons | `icons/icon` |

## Warning

**This tool can modify your WinCC OA system configuration and runtime data.** Changes directly affect your SCADA system. Use at your own risk and test in a safe environment before production use.
